SOC Lab: Detecting Suspicious Windows Logins with Splunk

A hands-on home lab built alongside the Google Cybersecurity Certificate and TryHackMe's Pre-Security path. I installed Splunk Enterprise, ingested my own Windows Security event logs, and investigated a real failed-login event end to end.

1. Detection

Search used to surface failed login attempts (Windows Event ID 4625):

index=main EventCode=4625

Result: 2 events matched — corresponding exactly to a deliberately mistyped password at the lock screen.

2. Investigation

splunk — raw event detail, EventCode=4625
splunk — failure information & network details
FieldValue
Logon Type2 — Interactive (local login)
Failure ReasonAn Error occurred during Logon
Status / Sub Status0xC000006D / 0xC0000380
Source Network Address127.0.0.1 (localhost)
Caller ProcessC:\Windows\System32\svchost.exe
Authentication PackageNegotiate
  • Logon Type 2 confirms an interactive attempt at the physical machine, matching the lock-screen test.
  • Source 127.0.0.1 confirms the attempt was local — in a real environment, the same search against an external source IP with repeated failures would indicate a brute-force attempt instead.

3. Turning it into a repeatable detection

Extending the search to group failures by account and source — the first step toward a real brute-force alert:

index=main EventCode=4625
| stats count by Account_Name, ComputerName, Logon_Type, Source_Network_Address
splunk — aggregated statistics view

4. MITRE ATT&CK mapping

T1110 — Brute Force (T1110.001 — Password Guessing)

Repeated Event ID 4625 entries against the same account — especially from an external source — are a primary indicator analysts use to detect this technique in production environments.
